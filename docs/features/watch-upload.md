# 监听上传

## 介绍

此功能用于自动上传录制目录中的视频：选择一个文件夹，软件会周期性扫描它，把新出现的视频自动加入 B站上传任务队列，无需手动一个个添加。

适合「录制软件不支持 webhook」或者「录完就丢在一个目录里」的场景，等于给一个普通文件夹接上了自动化上传。

## 使用方法

1. 打开「工具」 → 「监听上传」
2. 点击「添加」新建一条监听配置
3. 选择需要监听的文件夹，并选择上传预设（预设决定了标题、简介、分区、标签等投稿信息）
4. 保存后会立即检测一次，之后按配置的轮询间隔自动扫描

软件启动时也会立即检测一次，因此之前没上传的视频会在启动后自动补传。进入该页面或点「立即检测」也会触发一次扫描。

## 配置项

| 配置                 | 说明                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| 监听文件夹           | 需要监听的文件夹，一条配置对应一个文件夹                                 |
| 上传预设             | 上传使用的投稿预设，之后该文件夹的视频都默认使用这个预设                 |
| 轮询间隔（秒）       | 扫描文件夹的间隔，默认 60 秒，最小 10 秒                                 |
| 静默时间（秒）       | **最新文件的等待时间**，默认 86400（1 天），见下方说明                   |
| 启用                 | 是否启用该配置                                                           |
| 跳过最新文件         | 默认关闭，开启后最新的文件不会自动上传，见下方说明                       |
| 审核通过后移除源文件 | 开启后，稿件审核通过时把本地源文件移入回收站                             |
| 文件匹配规则         | 只有匹配的文件才会被处理，留空使用默认规则 `\.(mp4\|flv\|mkv\|ts\|m4s)$` |
| 忽略文件正则         | 匹配的文件会被忽略                                                       |

## 文件什么时候会被上传

录制中的视频会一直被写入，提前上传会得到一个不完整的文件。判定规则如下：

1. **已经有更新的文件出现** → 说明这个文件已经写完了，直接上传
2. **文件刚被写入过**（不足一轮扫描）→ 先等一等
3. **文件大小还在变化** → 说明仍在写入，继续等
4. **最新文件**：它是唯一可能还在录制的文件，所以默认**要等满「静默时间」（默认 1 天）没有变化**才会自动上传

也就是说：

- 录完一个视频后接着录下一个，上一个会马上（轮询间隔内）自动上传
- 正在录制的那个文件不会被误传
- **最后一个视频**：录完后不确定你是否还会继续录，所以等满静默时间（默认 1 天）后会自动上传；不想等就在「等待上传」里点「立即上传」

被判定为「还需要等待」的文件会显示在页面的「等待上传」区域，并标注具体原因。

::: tip 为什么默认是 1 天
这是为了防止「暂停录像」被误传：暂停时文件不再变化，如果等待时间太短（比如 60 秒）就会被当成录制结束而上传。

如果你更希望尽快上传最后一个视频，可以把静默时间改小（例如 600 秒）；代价是长时间暂停录像时可能被提前上传。

配置里的「**跳过最新文件**」是更严格的选项：最新文件**永不**自动上传，只能手动点「立即上传」。
:::

## 上传记录

页面下方会列出所有已处理的文件，包括上传状态（上传中 / 已完成 / 失败）与失败原因。

- 上传进度可以在「任务队列」页面查看
- 上传用的是配置里选择的**上传预设**，和「B站上传」页面同一个上传入口，标题/简介等模板会正常解析
- 删除某条记录后，该文件会被视为未上传，下次扫描会重新上传
- 「清空记录」会清空全部记录（谨慎使用，清空后所有文件都会被重新扫描）

## 上传失败与重试

监听上传调用的就是「B站上传」页「立即上传」用的那个接口（`POST /bili/upload`），一个文件一个上传任务，参数校验和提交逻辑完全一致。

只有成功上传过的文件才会被跳过，所以不会出现「失败一次就永远不上传」的情况。

- 上传失败会**弹窗提示具体原因**，无需去翻日志
- 失败的文件会在 **5 分钟后自动重试**，页面顶部也会提示失败数量
- 失败原因会显示在「上传记录」里，也可以点该行的「重试」立刻重试
- 软件重启时，处于「上传中」的记录会被标记为失败并重新上传（因为重启后不可能还有正在进行的上传）

## 排查「为什么没上传」

每张监听配置卡片上会直接显示当前状态：

- **文件夹**：匹配到多少个文件（显示「文件夹不存在」说明路径失效）
- **本次可上传 / 等待中**：分别有多少个文件可以上传、还在等待
- **已成功 / 发送中 / 失败**：各类记录的数量
- **B站账号**：实际使用的 UID（显示「未登录」说明还没登录，此时不会上传）
- **预设标题模板 / 分P标题模板**：实际取到的上传预设内容，和「B站上传」页用的是同一个预设
- **最后错误**：最近一次失败的原因，例如「投稿预设校验失败：xxx」

上传前会做和手动上传一样的投稿参数校验，校验不通过会直接把原因写进上传记录。
